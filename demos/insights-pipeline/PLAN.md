## 0. 设计总纲

1. **观众是第一次来**：打开页面的人不知道 /insights、不知道知识库。叙事要自己建立背景。
2. **要帅，不抄分镜**：借零大学的"质感"（3D 沉浸、节奏交错、进度可感、情绪化色彩、数据即场景物体），叙事结构完全独立：**黑盒揭晓**。
3. **措辞不虚构**：所有流程、数字、机制锚定两篇知识页。cap 约值用"约/上限"措辞；推测用"合理推测"措辞。演示数据标注"合成示例"。
4. **文案政策**（2026-07-31 初版；**2026-08-07 演出基线建立后以 `docs/audience-baseline.md` 为当前权威**，本节口径已随演出化更新）：
   - 观众是第一次进场，背景由演出自己建立，禁止假设任何前置知识（基线 §1.1）
   - **演出优先于演示**：观众看的是一场连贯的演出，不是功能演示；术语/数字/界面元素服务于剧情推进（基线 §1.2）；禁用清单（「本演示」整类 / 卖点罗列腔 / 说明书腔）见基线 §2
   - **一屏一件事**：展柜三定律（展品亮展厅暗 / 展品静观众动 / 展签贴边）；信息量放开但排版分层——大字核心句给方向 + 小字展开段给细节；序章 3 秒原则「一次摆好 → 扫一眼 → 按住走」
   - 术语首现给大白话，中文为主、术语保留原文
   - 语气：科普第一，适度俏皮（HUD 提示、引导语、彩蛋句），主体科普段落保持专业

**叙事弧：黑盒揭晓（三幕）**

```
序章 · 你的视角    一次摆好：它在看你 —— 读了你这个月的话，写了份关于你的报告
  │                      ↑ 被看见的悬念："回车之后，那段时间里到底发生了什么？"
  ▼
第一幕 · 数据      引擎认识你的历史：命中 → 扫盘 → 缓存（快、奇观、冷青/冷蓝）
  ▼
第二幕 · 理解      对话被压缩、被读懂：过滤投影 → 打标签（慢、重场戏、青紫）
  ▼
第三幕 · 生成      报告长出来：七章并行 → 总览 → 落盘交付（仪式高潮、琥珀）
  ▼
尾声 · 回到你的屏幕   那两行英文 + file:// 链接再次出现 —— 但你现在懂了
```

## 1. 参考解剖：why.zero.university（素材库）

> 本节是素材库参考（解剖对象的技术栈/机制/质感），非本项目方案；本项目的技术方案见 §3。零大学是起点参照，不抄分镜（§0.2）。

### 1.1 技术栈（chrome-devtools 实测验证）

Vite 单 bundle · 原生 Three.js（WebGL2 超采样 2560×1275 + 大量自定义 shader）· GSAP · Howler · 自研 lerp 平滑滚动（wheel 完全接管）· 自定义光标图集。

### 1.2 机制层（bundle 静态分析 + 合成输入逐阶段验证）

| 机制 | 验证证据 |
|---|---|
| 多阶段时间轴：每段独立滚动预算 scrollVh + gate 自动滚动过渡段 | segments：stage1 175vh → gate 50vh(autoScroll) → stage2 250vh → … |
| 滚动接管：wheel deltaY×35 → targetScrollPos → rAF lerp，body overflow hidden | `_onWheel` 源码 |
| TAP HOLD：按住按钮，SVG 进度环填充，时长达标触发 | `Tg` 类源码 + 实按验证（XP 300→400） |
| 画圆手势：≥330° 且圆度误差 <35% 且闭合 | `_checkZeroGesture` + 实画验证 |
| XP 计量：每推进 +100，数字滚动动画 | 全程采样 100→500 |
| HUD：XP / 任务状态 / 标尺导航 / SCROLL 指示 / 音频开关 | DOM 全程 |
| 终局：证书相框 + 公司卡片视频 + Join Beta 表单 | `frame-open`、`origami_certificate.webp` |

### 1.3 质感层（十张截图拆解 + 主人确认吸收）

零大学真正的帅不在机制而在**叙事设计**，拆解如下（grok 识图反馈 + 代码层验证交叉）：

1. **叙事短片结构**：十屏 = 十个情绪节拍（相信→承诺→触碰→崩坏→怒骂→数据→金钱→燃烧→真相→抉择），每屏只服务一个节拍，信息密度克制
2. **一个贯穿的 3D 隐喻主体**：全场是"一只手"—— 概念可视化，不为炫技堆模型
3. **色彩即情节**：白/薄荷绿（希望）→ 红（幻灭）→ 暗绿黑（真相），场景复用 + 调色反转制造冲击
4. **数据不做列表，做成场景物体**：玻璃碎片=统计卡片、飞舞纸片=名人语录，信息本身成为场景美术
5. **字即图形**：超大 display 字 + 小 caption，大负空间，字与 3D 主体咬合
6. **统一交互语言**：TAP HOLD 贯穿全场，交互即剧情
7. **固定 HUD 不抢戏**：XP、Join Beta、SOTD 常驻，建立产品感
8. **情绪优先于功能说明**：先让人"感受到"，再给数据

**我们吸收为：三幕情绪节奏 + 光河贯穿主体 + 重场戏独立奇观 + 数据即物体 + 字阶排版。**

## 2. 叙事设计

### 2.1 序章 · 开场（被看见）——已定稿

> **实施依据：`docs/PROLOGUE-REDESIGN.md`（v2，修订①②③，2026-08-11 终稿）。本节旧草案（"回车之后，发生了什么？"版本）作废，只保留指针与现状摘要；细节以规格文档与 `src/prologue.js` 代码为准。**

**定位**：序章 3 秒只做一件事——让观众意识到「这次是它在看我」（它读了你这个月的话，写了份关于你的报告）。意识到那一瞬，观众自己会按，不用推。

**时间轴（≈3s）**：一次摆好（标题逐字锐化保持暗 → 副题+钩子合拍 → 报告条目块整块落位 → 尾部轻落）→ 0.9s 悬置（首行 ▌ 光标闪烁）→ 80ms 停顿真空 → 0.98s 可走 → 按住 1.25s 打满（**2026-08-12 转场重构**：按住期 520 颗星 WebGL 恒星坍缩收进环心 + 圆环坍缩 1→0.25，松手原速原样回退）→ 环满：月球布光 0.7s 扫向全屏（白→青渐变，文本层被光洗掉）→ 青雾峰值帧层交换 → S1 面板落下（硬切，S1 从青雾中现出）。详见 docs/PROLOGUE-REDESIGN.md 修订 ④~⑨。

**文案终稿（八块）**：
1. 标题 `/insights`（字即图形，暗着，通电才亮）
2. 副题 **这个月，你都和它说了什么？**
3. 钩子 **你每天指挥它干活。今天轮到它点评你。**（`<br>` 强制两行；「点评你」青色高亮放大）
4. 报告条目六条：38% 的摩擦，同一个原因（首行特殊条目带 ▌）／10 场会话，8 场在修 bug／4 小时的会话，最长的一次／3 场对话，同时开着／23 个话题，一半绕不开…／600+ 次 Edit 工具调用，背后原因是…（透明度渐进 100%→18%；38%/600+ 取主人真实月报校准）
5. 生成过程单句：**读你一个月的会话记录，写成七章，归纳成一份 HTML 报告。**
6. 点题句 **报告是它写的。句句说的是你。**（暗态在场恒定——2026-08-12 修订 ④：琥珀揭示随揭示拍删除，退场被月球白光吞没）
7. 来源行：基于 @cometix/claude-code 2.1.209 静态源码分析 + 两个知识页链接（压一行贴底，不可删字）
8. 按住区：左标注「按紧它，别松手」→ 圆环（环心 = /insights）← 右标注「等它转满」

**布局**：三段声部（masthead 左上 6vw → 报告卡中左 28vw → 判决右锚 1.5vw，左上→右下对角流）+ 右上角 WebGL 真球体月球（斜轴 23.4° 自转 60s/圈，贴图本地化 public/moon.jpg）+ 繁星 160 + 心跳星 10（固定种子 LCG 可核验）。

**裁决（2026-08-11 主人）**：无键盘通道（tabindex 删除 → 圆环不可聚焦，根治焦点方框）；无降级（全程要求 WebGL2，不支持即白屏）；合成注记移除（38%/600+ 已校准真实月报，10 场/4 小时/23 话题仍为合成值）。

### 2.2 主体 · 引擎的八站（三幕）

**贯穿主体：光河** —— 一条发光的数据河 = 你的历史会话。河流宽度 = 信息量。全程跟随同一条河被逐层加工；重场戏站（S4/S5/S6）河流展开为独立大奇观。**序章六条报告条目是全剧谜面，S4/S5 的标签与 S6 的聚合是谜底**（暗线，m4/m5 规格应显式设计）。

**推进节奏**：站内滚动探索（光河流动）↔ gate 自动过渡（镜头转场：幕内轻量 gate 河全程全亮 + 相机贴河滑行，幕间 3.5s 黑场）。统一交互语言：**滚动=看，按住=走**。

**TAP HOLD 全剧仅 3 次（仪式时刻）**：
1. 序章 —— 按住"运行 /insights"（观众按下回车）✅ 已落地（2026-08-11）
2. S3→S4 —— 进入第二幕"模型介入"（按住 = 把数据交进模型手里）⏳ 待 m4 接入（当前 gate1to2 为自动黑场）
3. S7→S8 —— 交付仪式（按住 = 落盘生成报告）⏳ 待 m5 接入

其余站间用滚动 + gate 自动过渡，避免重复疲劳（参照零大学 10 屏仅 3 处按住）。

### 2.4 措辞规范

1. 术语首现给大白话：facet —— 模型给每个会话打的语义标签；有损投影 —— 把原始记录压成简明文本，细节有取舍
2. 中文为主，术语保留原文（`/insights`、facet、meta、JSONL、At a Glance、`<message>`）
3. 数字措辞诚实：投影截断"约 500/300 字符"；cap 值说"有数量上限"；精确值只来自知识页原文
4. 动机措辞分级：源码可证 → "引擎会…"；推测 → "合理推测"
5. 不虚构：不展示真实报告的完整内容（只有合成示例，且标注）。**引擎是纯代码流程、没有界面**——演示中的终端/盒子/标签等均为**合成视觉**，必须同屏标注（m3-design §4 S1 措辞诚实注记；终端黑话原则见基线 §3）
6. 界面禁用 emoji 字符（U+1F000+ 码位，装饰/图标/语气词一律不用）；排版符号（→ ★ ※）不受限，俏皮靠文字实现
