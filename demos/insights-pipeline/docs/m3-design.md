## 1. 设计总纲:「帅」的定义

### 1.1 一句话定位

> 第一幕 = 一条数据河诞生的奇观:本地、确定、唰唰唰。观众第一次看见「自己的历史」变成一条发光的河。

- 「本地」:全在你机器上,确定性、安全感 → 情绪底色是冷蓝(信任/清晰)
- 「确定」:每一步都有明确的视觉因果(命中 → 亮起、扫描 → 星云、分流 → 双色)
- 「唰唰唰」:快节奏,数据流动的爽感,不拖沓

### 1.2 对标标准(Awwwards 级,拆成五条可执行特质)

SOTD(每日最佳)获奖站点的五个共同特质(Awwwards 评审口径:Design / Usability / Creativity / Content 四项 8.5+),对应我们的落点:

| 特质 | 含义 | 本项目的落点 |
|---|---|---|
| 意图化叙事 | 每个滚动/点击/悬停都推进叙事 | 滚动 = 看(光河流动),站内事件 = 叙事节拍(S1 命中 → S2 扫盘 → S3 分流) |
| 编排动效 | 动画引导注意力,而非装饰 | 每站只有一个「视线焦点」,其余元素让位 |
| 感官丰富度 | 辉光、景深、速度层次、纹理 | 光河四层粒子:芯/身/尘/火花,辉光克制,流速可感 |
| 技术工艺 | 60fps、加载快、降级优雅 | 单 draw call 粒子(§3.1)、DPR 钳制、后处理可降级(§3.4) |
| 克制与负空间 | 一个重心物体配大留白,胜过堆元素 | 第一幕的「重心」只有光河,三站是河的三种形态,不额外堆模型 |

**「克制」的具体要求**:一屏内只让一个东西「抢眼」——要么是光河,要么是站的主角物体(终端/星云/缓存盒),其余全部压暗或缩小。宁可空,不要满。

### 1.3 情绪目标

- 观众情绪曲线:好奇(序章遗留)→ **豁然**(数据被看见:原来我的历史长这样)→ 期待(接下来会被怎么处理?)
- 色彩情绪依据(数据可视化情感色研究):蓝绿集中 = Calm/Trustworthy;第一幕冷蓝 = 信任与确定,与「本地、确定」的叙事自洽
- **节奏的事实依据(知识页)**:analyzing 之后那段几十秒到几分钟的等待,绝大多数时间花在报告引擎的内部模型调用上(mechanism 页俯瞰:「上面那条占用了绝大多数时间」)——本地 IO 环节(枚举/缓存检查/读盘)本身很快。因此第一幕(数据,本地确定)用「快」节奏、第二幕(理解,模型介入)用「慢」重场戏,是有事实依据的幕节奏设计(PLAN §2.2),不是凭空取舍
- 节奏:第一幕三站总时长 ≈ 14~18s(滚动驱动的等效密度,站内 5~15s 看完一站),不留恋

### 1.4 「帅」的来源与超越点

- **来源**:零大学质感拆解(PLAN §1.3:叙事节拍 / 贯穿隐喻 / 色彩即情节 / 数据即物体 / 字即图形 / 统一交互语言 / 固定 HUD / 情绪优先)——第一幕全部沿用
- **超越点(第一幕特有的「帅」)**:光河不是静态场景,是**有生命的流**——粒子每一帧都在流动,「数据在运转」是持续的视觉事实。零大学的静态奇观 + 我们这条动态的河 = 第一幕的辨识度
- 数据即物体是第一幕的核心手法:会话 = 星星、缓存 = 盒子、命令 = 字符。信息本身成为场景美术

**与零大学的差距清单(主动拉开差距的 8 条)**:

1. 数据编码到视觉变量:河宽=信息量、星亮=mtime、盒亮=写/复用——**可解释的视觉**,不只是叙事道具(前提是 §2.5 数据层)
2. 持续空间主角:光河跨 S1~S3 不断线,只变形不消失(§6.1)
3. 终端工艺:等宽、块状光标、命中表、状态列——**操作感**(零大学偏影像/3D 文案)
4. 空闲生命力:停止滚动时粒子仍 idle 呼吸,不死图
5. 状态对比语法:「亮 vs 哑」冷静对比(写 vs 复用)——比戏剧化特效更「系统、聪明」
6. 字永远净:3D 可以脏(粒子/景深),文字层永远锐利(合成顺序在最后,§3.4)
7. 微反馈闭环:每个 hit/reuse 有 80~120ms 可见反馈,不靠大动作
8. 克制细节:扫描线只出现在终端面板内(3~5% opacity)、色差只在高速转场 0.3s 内(≤0.8px)、Bloom 高阈值只吃最亮的芯

## 2. 全局视觉语言

### 2.1 光河 = 贯穿主体(第一幕的核心资产)

- **形态**:连续粒子流,代表历史会话数据
- **河宽 = 信息量**:粒子条带宽度由数据量驱动(`w = wMin + k × log1p(infoVolume)`,§2.5 数据层供给 infoVolume);S1 源头窄 → S2 汇聚最宽 → S3 分流收窄分叉——宽度变化本身是叙事
- **持续流动**:粒子沿河方向漂移,「数据在运转」永不静止(除非 reduced-motion)
- **三站形态**:S1 河从终端底部「生出」→ S2 河从星云中「抽出」→ S3 河「分流」成两条。河是三站的主线,站是河的注脚

### 2.2 字即图形(PLAN §4 决策,已定)

- 图形标记一律字符(字符 + 光晕)+ 几何 + 3D 物体,不引图标库(零 SVG icon)
- 第一幕的字符形态:终端命令字符(S1)、会话/缓存标签(S2/S3 悬停面板)、站号字符(HUD 已有)
- 排版符号(→ ★ ※)不受限,禁 emoji 字符(U+1F000+)

### 2.3 色彩

**原则:色相随幕(冷蓝),亮度分层(场景浓、UI 淡、芯最亮)。** 背景禁止纯黑 #000(会吞光)。

| 角色 | 色值(基线,可微调) | 语义 |
|---|---|---|
| 背景 | `#05070C`~`#0A0E18`(现 body 色 #05070d 已符合) | 近黑微冷 |
| 第一幕基调 | 冷蓝 `#7dd3fc` 系(与 HUD act1 微染同色相) | 数据、确定、信任 |
| meta 语义色 | 青 `#7dd3fc` 系(PLAN 语义,比 grok 的青绿更冷) | 纯计算、可复用(S3) |
| facet 语义色 | 品红 `#f472b6` 系 | 模型判定、花 token(S3) |
| 复用/未变 | 不发光(暗盒,§4.3) | 「文件没变就复用」的视觉事实 |
| 辉光 | alpha 0.3~0.7,不铺满 | 克制——过量辉光是廉价霓虹 |

**光河内部色阶(河的「素描关系」,与 HUD 同色相、不同层:UI 文字淡,场景粒子浓)**:

| Token | Hex | 用途 |
|---|---|---|
| river.ember | `#E8F4FF` | 源头点亮瞬间的 HDR 峰(冷白) |
| river.core | `#B8E7FF` | L0 芯核(偏白青,定义脊线) |
| river.body | `#4AA8FF` | L1 主体(稳定冷蓝) |
| river.deep | `#1A4A8C` | L2 尘雾 / 远场(暗蓝) |

**沿河色彩渐变**(参数 `t` = 沿路径 0→1):源头 `ember → core`(冷白)→ 中段 `body`(稳定冷蓝)→ 远端 `deep` + 轻微降饱和(退场)。S3 叉口后:粒子色 = `mix(meta, facet, branchId)`。

### 2.4 排版字阶(与序章/HUD 同体系,不新造)

### 2.5 数据层:合成数据 sessions.js(「数据编码到视觉变量」的前提)

PLAN §2.5 已定:虚构 12~15 个会话,围绕本知识库工作流(入库/机制分析/知识页打磨等),手写 meta(时长/消息数/工具/语言)与 facet JSON(目标/满意度/摩擦/类型)。

- 新文件 `src/data/sessions.js`,导出合成会话数组(每个:会话名、mtime、消息数、工具数、token、meta/facet 摘要字段)
- **视觉变量全部从数据来**(这是「可解释的视觉」的实现保证):
  - 光河宽度:每站的信息量 = 相关会话数/消息量(源头发源窄 → 星云汇聚全量最宽 → 分流按 meta/facet 拆分)
  - 星云:亮星 = 12~15 个合成会话(mtime 越新越亮,§4.2 公式);暗星 = 背景其余历史(数量自由,仅构成氛围,标注合成示例)
  - **分流比体现「facet 更保守」**(知识页事实:meta 单次上限 200 vs facet 50,4:1):meta 支流量明显大于 facet 支(≈70/30,可按会话数据统计;55/45 的势均力敌会丢掉「成本不同待遇不同」的视觉语义)
- 数据在 UI 上标注「合成示例」(PLAN §2.4 措辞诚实)

## 3. 光河管线 river.js 规格

### 3.1 粒子系统(性能第一)

- **单 `THREE.Points` + `ShaderMaterial`,一个 draw call**(与 §7.1 验收「粒子 draw call = 1」一致)——四层不是 4 个 Points,是**同一 buffer 内按 layer 属性分区**(aLayer 属性 + drawRange 段,或全部粒子带 aLayer、shader 内按层调参)
- 粒子总数 ~1e4:预分配 Float32Array 上限 + `drawRange` 控制实际数量,避免重建 buffer
- `AdditiveBlending` + `depthWrite: false`(发光粒子标准组合,重叠处偏白 = 真发光感)
- `devicePixelRatio` 钳制 2(已有约定)
- 顶点动画全部在 shader 里做(uTime 驱动),**不做 JS 逐粒子循环**——这是「1e4 粒子 60fps」的唯一正解

**四层粒子结构(帅的关键:人眼只认三层亮度,缺一层就像「粒子 demo」而不是「光河」)**:

| 层 | 角色 | 数量(总 ~1e4) | 尺寸 px@1080p | 亮度 | 用途 |
|---|---|---|---|---|---|
| L0 Core | 河芯高亮核 | 800~1200(~10%) | 2.8~4.2 | 1.00 | 定义「河」的脊线 |
| L1 Body | 主体流量 | 5500~6500(~60%) | 1.4~2.4 | 0.45~0.65 | 河宽、信息量编码 |
| L2 Dust | 弥散尘雾 | 2500~3000(~25%) | 0.8~1.6 | 0.12~0.22 | 体积感、景深填料 |
| L3 Spark | 事件火花 | 200~400(~3%) | 3.0~6.0 出生即衰 | 短寿命 | 命中/分流/写盒瞬间 |

- 纹理用 64² 径向软斑 + smoothstep 外圈,**禁止硬圆点**;中心 alpha 1.0、半径 40% 内保持高亮、外 60% 指数衰减
- 粒子截面用**高斯分布**(`offset = gauss() × 半宽`),边缘粒子更慢更暗——矩形填充=程序感,高斯=流体感

### 3.2 shader 规格

```
属性(attribute):
  aSize      粒子尺寸(层别:L0 大 / L2 小)
  aColor     粒子基色(层别 + 沿河渐变参与)
  aPhase     相位偏移(呼吸/闪烁错峰,避免全河同步)
  aAlpha     透明度(远层更透)
  aLayer     层 ID(0~3,shader 内按层调参——单 draw call 的关键)

uniforms:
  uTime         全局时钟
  uRiverWidth   河宽(信息量,三站动态,§2.5 供给)
  uFlowSpeed    流速(站内事件可脉冲,§3.3 分站值)
  uColorA/B     颜色渐变端点(沿河渐变 + S3 分流:青 → 品红)
  uPixelRatio   DPR 钳制

vertex:位置漂移(uTime × 流速,沿河向)+ 噪声微扰(幅度随 uTime 缓慢变化)+
        gl_PointSize 尺寸衰减(300 / -mvPosition.z,clamp 后)
fragment:软圆粒子(smoothstep 衰减)+ 辉光层次(按 aLayer 调亮)
```

### 3.3 河的「生命感」(帅的关键)

1. **流动**:粒子沿河方向持续漂移——流速分站:`vS1` 1.4~1.6(点亮后加速「唰」)、`vS2` 0.9~1.1(从星云抽出略慢显「拽」)、`vS3` 1.2 主段 / 分叉后 0.85(分流后减速入盒)
2. **呼吸**:噪声扰动幅度 0.04~0.08 × 河宽(curl/simplex 横向扰动,频率 0.6~1.2),河不是僵直光带;空闲时(无滚动)粒子仍 idle 呼吸,不死图
3. **宽度叙事**:河宽 = 信息量(`w = wMin + k × log1p(infoVolume)`),S1 源头窄 → S2 汇聚最宽 → S3 分流收窄分叉——与滚动/叙事绑定
4. **事件脉冲**:站内关键事件(命中/抽出/分流)时 L3 火花短暂爆发 + 粒子加速,把注意力引到事件点(编排动效的落点)
5. **粒子生命周期**:出生 0~12% 放大(easeOutCubic)、末 15% 收缩;alpha 0~8% fade-in / 8~80% hold / 80~100% easeIn fade-out——粒子有「生死」,河才像活的
6. **隐藏分(低成本高观感)**:鼠标/滚动时光河横向微偏 ±2%(Active Theory 式响应,勿抢戏);粒子接近实体几何(S3 缓存盒)时 soft particle 深度渐隐,防硬穿插——盒前吸入的粒子不「穿模」

### 3.4 景深与后处理(打磨层,全部可降级)

**景深**:焦平面服务叙事,非全局模糊——S1 焦平面=终端/源头(近)、S2=星云中景、S3=缓存盒(中近);远场 blur 2~5px(低画质 tier 关闭 DOF);**文字/终端永远锐利**(tone map 后合成,3D 可以脏、字必须净)。

**后处理链(Awwwards 级质感,标注范围)**:这是「打磨层」——M3 核心(粒子/三站/联动)完成后若时间与性能允许则上,否则**明确延到 M6**(PLAN §3 性能预算严格,单 canvas + DPR 2 是硬约束):
1. Bloom:threshold 0.82~0.88、strength 0.35~0.55——阈值偏高,只让最亮的芯/火花开花,满屏糊光是掉档标志
2. DOF(tier 可关,低画质关闭)
3. Film grain:1.5~2.5%(低成本高质感,值得留)
4. 极轻 vignette(角落 -8%)
5. 文字/终端在 grain 之后合成
6. 色彩:HDR 写后 tone map,叠合峰值允许 >1.0 但避免白斑死烧

### 3.5 S1 终端 DOM 与 3D 光河的锚点机制(工艺点,防卡壳)

- 终端面板在 DOM 层(`#ui`,视口固定定位),光河在 3D 层(`#scene`)
- **锚点机制**:进入 S1 时,用 `getBoundingClientRect()` 取终端面板底部中心在屏幕上的坐标,换算为 3D 世界坐标(逆投影)作为河源头位置;滚动/相机移动时源头保持「接入终端底部」——即**源头是世界坐标固定点,终端是视口固定元素,二者通过初始对齐 + 相机路径约束保持衔接**
- 简化策略(推荐):S1 内相机几乎不动(相机沿河推进从 S2 才开始),源头在 S1 期间固定在屏幕对应位置即可;站内滚动只驱动粒子与文案,不移动相机——把两层的同步负担降到最低
- 验收:滚动过程中河源头与终端底部的视觉衔接不脱节、不抖动

## 4. 三站场景规格

> 每站规格 = 构图(观众看到什么)+ 节拍(入场动画 3~4 拍)+ 站内滚动编排(文案与场景的进度映射)+ 数据即物体 + 文案锚点(PLAN 原文,不得改写删减)+ 验收。

**站内滚动编排(三站共用结构,「滚动 = 看」的叙事密度)**:

```
滚动进度 p (0~1,scrollVh 预算内):
  0.00~0.20  入场节拍(自动播放 3~4 拍,见各站)
  0.20~0.75  文案浮现:大字核心句 → 小字展开段(随滚动逐段进入,信息量放开,

### S2 扫盘 —— 会话星云

**构图**:一片星星点阵(独立 Points,数百颗可见,软圆粒子复用光河 fragment 的柔光),每颗 = 一个历史会话;光河从星云中「抽出」一段(扫盘的动作感);一颗最暗的星被弃置在角落(元会话)。

1. 星云展开:观众看到「你的历史 = 一片星空」(信息量的一瞥)

**数据即物体**:星星 = 会话,亮度 = 新旧,暗星 = 元会话被弃置。

### S3 缓存分流 —— 双色河 + 缓存盒

**构图**:河到达分流点,分成两条——meta(青)与 facet(品红),各流向一个缓存盒(几何体);未变的盒不发光(暗盒),需要更新的盒亮起。

**分流细节**
- 分叉处:Y 型,夹角 **28~36°**(过锐像剪刀,过钝像没分);分叉动画 0.45~0.65s(easeInOutCubic 路径 morph);叉口前 8~12% 路径为色过渡带(青 → 双色 smoothstep);叉口处 L0 核短暂劈成两股(视觉上「劈开」)
- **两支流量比(知识页事实编码)**:meta 支明显宽于 facet 支(≈70/30,按 §2.5 数据统计;知识页:meta 单次上限 200 vs facet 50——facet 保守,河窄 = 保守)**——「facet 河窄」本身是「花 token 所以保守」的视觉事实,与 55/45 势均力敌的对称感相悖**
- 缓存盒:几何盒(自发光材质,emissive 强度驱动状态——我们无光照场景,盒不需要被照亮,发光 = 强度);盒子 + 等宽标签字符(字即图形,不雕花)
- **盒三态视觉语法(不发光 = 复用)**:
  - **Write/更新**:盒边对应支颜色 1.5px + 外晕 8~12px,粒子吸入 + 盒 intensity 0→1
  - **Hit/复用(mtime 未变)**:同形暗底、灰色细边 0.5px、**无外晕、无填充光**;粒子在盒前偏转/滑过;**收到碰触时给一次 80ms 边线闪灰**(确认「读到了」)然后灭——不是死寂
  - **Idle**:仅轮廓 15% alpha
  - 关键细节:**同几何、不同能量**——形状一致,只关 emissive,观众才能对比「有的亮有的哑」
  - 标签:极小等宽字符 `HIT · mtime=` / `SET · written`(非 icon)

**节拍(3 拍)**:
1. 汇聚:河到分流点,宽度达第一幕最宽(信息量全量)
2. 分流:双色分叉,meta 青 / facet 品红各走各道
3. 入盒:一盒亮(更新)、一盒暗(复用)——对比成立,视线落在「差异」上;粒子接近盒速度 ×1.3 后 0.15s 内 alpha→0(吸入);全部结算后两支河变细,盒阵列呈「有的亮有的哑」的节奏图案——**这就是信息图**

**数据即物体**:盒 = 缓存,发光 = 更新成本,暗 = 复用。成本与确定性,待遇不同(PLAN 文案原意)。

**文案锚点(PLAN §2.2 S3)**:「几百个会话,每次都从头分析太慢。引擎有两层缓存:meta 是算得出来的统计 —— 时长、工具次数、token 消耗,文件没变就复用;facet 是模型才判断得了的语义标签 —— 目标、满意度、摩擦,每次抽取都花 token,所以保守。两层分开存,更新互不误伤。成本与确定性不同,待遇就不同。」

**验收**:双色一眼可辨(青=meta/品红=facet)、亮暗盒对比成立、复用盒有一次确认闪但不维持发光、文案锚定。

## 5. 动效节奏(第一幕「快」)

| 层级 | 节奏 |
|---|---|
| 粒子流动 | 持续(基准速),站内事件时脉冲一次 |
| 站内节拍 | 每站 3~4 拍,每拍 0.4~0.8s,错峰(不齐步) |
| 站间 | gate 黑场自动过渡(幕间 3.5s 不动;幕内站间轻量,见 §6.1) |
| 滚动 | 站内滚动 = 看(已有虚拟滚动,不动;编排见 §4) |
| TAP HOLD | 第一幕无按住(全剧仅 3 次,序章已用 1 次) |

**错峰原则**:同一时刻只有一个动画在「动得明显」,其余是持续低层流动。全屏齐动 = 廉价感。

**「唰唰唰」操作定义**(第一幕节奏的量化标准):
1. 短间隔重复确认:命令命中 stagger 45~60ms(人可感的连击)
2. 无长 fade:UI 入场 fade ≤ 150ms,超过即拖沓
3. 硬状态边沿:hit / write / reuse 用 1~3 帧的 flash,不用 600ms soft fade
4. 相机少犹豫:dolly/pan 单调向,不回摆(第一幕不要「诗意游荡」)
5. 总时长参考:第一幕 ≈ 14~18s(滚动驱动下的等效密度,站内 5~15s 看完)

**缓动速查**:UI 列表入场 `easeOutExpo`(快出头尾干净)/ 相机 `easeInOutQuad`(稳)/ 粒子路径 morph `easeInOutCubic` / 闪光 `linear` 或 `easeOutQuad` ≤ 120ms。

**reduced-motion**:粒子静止、节拍直接呈现、后处理(若上)降级为无(已有约定,延续)。

### 6.1 架构决策:三站共享同一光河(空间模型)

PLAN §2.2 的叙事是「**全程跟随同一条河被逐层加工**」——这决定第一幕的空间模型:

```
        [S1 终端]                [S2 星云]                [S3 缓存盒]
         ┌──────┐              ★ ★ ★ ★ ★               ┌────┐  ┌────┐
         │ > /  │                 ★ ★ ★                  │meta│  │facet│
         └──┬───┘                 ★ ★ ★                  └─┬──┘  └─┬──┘
            │ 源头                    │ 抽成河               │      │
   ●━━━━━━━━┛ 窄                     │ 宽                   │ 分流 │

- **三站共享同一个光河实例与坐标系**,站 = 相机沿河的观察位置(河是连续线,站是河上的事件点)

5. S1:块状光标 ~530ms 周期、命中 stagger 连击可感、analyzing 晚于命令表出现、源头点亮与 hit 绑定、DOM-3D 锚点不脱节
6. S2:mtime→亮度单调映射可读、闪烁非同步、弃置星明确「不入河」、星→流有可见的物质转化过程
7. S3:青/品红分叉一眼可读、发光盒 vs 哑盒并置对比、复用盒有一次确认闪但不维持发光

**整体**
8. 色彩语义一眼可读:青 = 数据/meta、品红 = facet、暗 = 复用
9. 与序章/HUD 质感统一:字阶、辉光克制、无 emoji 字符;文字永远锐利(3D 脏、字净)
10. 节奏:无 >300ms 的无意义 fade、硬状态边沿、相机单调向不回摆
