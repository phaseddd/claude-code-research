# audience-baseline.md — 演出基线（观众体验规则）

> 本文件是 insights-pipeline demo 的演出基线：文案、数字、交互的全站统一规则。
> 适用对象：S4~S8（第二/三幕尚未实现）及此后任何一站、任何一次改动。开工前先对照本文件设计；完工后对照本文件自检。

## 1. 创作原则

1. **观众是第一次进场**：不知道 /insights、不知道 Claude Code、不知道知识库。所有背景必须由演出自己建立，禁止假设观众有任何前置知识。
2. **演出优先于演示**：观众看的是一场连贯的演出，不是功能演示。术语、数字、界面元素服务于剧情推进，不服务于罗列。零大学质感是目标，说明书质感是禁区。
3. **科普目标不变**：观众看完能懂「你按下回车后，后台发生了什么」。内容锚点：`analysis/concepts/claude-code-insights-prompts.md` + mechanism 页。
4. **措辞不虚构**：流程、数字、机制锚定知识页。cap 值用「约/上限」措辞；推测用「合理推测」措辞；演示数据一律标注「合成示例」，不展示真实报告的完整内容。

## 2. 开场白原则：钩子优先

- 序章开场白是钩子，不是说明书：先让观众想起「自己按下回车、屏幕卡住几十秒」的经历，再抛出悬念「这几十秒里发生了什么」。
- 禁用清单（演示腔 / AI 味，出现即返工）：
  - 「本演示」整类措辞（「本演示带你…」「本演示演示…」一律不用）
  - 卖点罗列腔（如「哪里顺畅、哪里卡壳、甚至还有几条建议」）
  - 产品说明书腔（如「本演示带你走进那段等待时间」）
- 允许保留：标题（悬念）、聊天窗示例（黑盒的「盒」）、按住按钮（演出互动的入口）、来源链接（小字不抢戏）。
- 流水线（扫盘→缓存→压缩→打标签→写七章→合成总览）是全剧地图，必须保留，但措辞像「故事预告」不像「功能列表」。
- 节奏检验：观众能否在几秒内见到钩子并走到按钮。信息量全平铺（多字阶 + 聊天窗 + 流水线同时上屏）即不合格。

## 3. 终端黑话原则

- 内部命令名（`session:list`、`session:stats`、`cache:probe` 等）与无解释的数字（如 MATCH 03/12 的分母 = 会话数）对观众是噪音，禁用。
- 优先「动作演出行」：不查手册也看得懂的语义行（如 `engine takes over · 报告引擎接手`）。
- 终端氛围不靠内容，靠等宽字体、渐显、hit 闪光节奏与光效——氛围与可读性解耦，两件事分别达标。
- 节奏（拍1 输入 / 拍2 命中 / 拍3 analyzing / 拍4 河亮）与动画编舞保持不变，换行不改节拍。

## 4. 数字口径表（站间自洽）

数字必须全剧一致，不得每站各自引入新数字。当前口径：

| 站 | 口径 | 说明 |
|---|---|---|
| 合成数据 | 11 个合成会话 + 1 个元会话 | `src/data/sessions.js`（元会话 isMeta，不入统计） |
| S1 | 无 MATCH 分母（不再出现 03/12 这类 x/12） | 分母 = 会话数，观众无法解读 |
| S2 | 11 颗亮星 + 1 颗元会话星 | 亮星 = 合成会话；暗星为背景氛围，不计数 |
| S3 | 「十几个会话」（不说「几百个会话」） | 与 11 个合成会话自洽 |

新增数字前先查本表；本表更新必须同步全站所有出现该数字的站。

## 5. 交互一致性原则

- **「回到序章」HUD 常驻**（hud-bar 内，序章→S8 全站一致）；任何站不得独享「重新体验」类按钮。
- **进度与因果可见**：状态不得「凭空出现」——进度条从 0 走起，观众要看到起点（如 0→62 用时 ~1.2s、easeInOut，再 62→100 与河变宽同步）；「从哪里来、到哪里去」每步可读。
- **gate 河连续**：河是同一个实体。幕内转场河全程全亮流动（minOpacity ≥ 0.9），不得出现「河若隐若现的暗场」；幕间黑场除外。转场中河段窗口切全河，让观众第一次看到河的全貌。
- **文案位置全站统一**：左列布局（`:root` 的 `--copy-col` 共享变量，站间改一处全生效），不搞单站居中。
- **可读性下限**：标签类最小字号与对比度按 S3 已落地标准（clamp(13px, 1.2vw, 15px)、`--ink-veil` 衬底保证背景上可读），任何站不得低于此线。

## 6. 文案基调（原则 + 代码指针）

具体措辞以代码为唯一事实来源（避免文档抄写与实现漂移），本节只列原则：

- **序章 = 钩子开场**：先抓观众自己的经历（按下回车、屏幕卡住几十秒），再抛悬念「这几十秒里发生了什么」。措辞见 `src/prologue.js`。
- **S1 终端 = 动作演出行**：语义可读、中英成对，不露内部命令名/分母。措辞见 `src/scenes/s1.js`（HITS）。
- **S3 缓存标签 = 语义可读**：`WRITE · 写更新` / `REUSE · 复用确认`，不露内部字段（无 `mtime=` 空值尾巴）。措辞见 `src/scenes/s3.js`。
- **检验**：新站文案写好后对照第 2~4 节自检（禁清单 / 数字口径 / 黑话原则），不以本节示例代替自检。

## 7. 与 PLAN.md 的关系

- **基线优先**：本文件是观众视角的创作依据；PLAN.md 是技术设计文档。两者冲突时以本文件为准（观众体验高于文档一致性），代码注释注明「演出化调整」。
- **PLAN.md 同步**：演出化改动涉及 PLAN 措辞时，在改动发生的那次提交里一并更新 PLAN，不在本文件记录待办状态。
